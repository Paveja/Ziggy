# Ziggy

## Purpose

A working, end-to-end food delivery marketplace where customers discover restaurants and place orders, restaurants accept and prepare orders, delivery partners pick up and deliver them, and admins and support staff operate the platform.

## Ground rules

- Use an original product name, logo, and placeholder images. Do not copy real brands' assets, trademarks, or restaurant data. Use fictional seed data.
- Put third-party integrations (payments, maps, SMS, and push notifications) behind interfaces with mock adapters by default, so the product runs locally without accounts or API keys.
- Build in phases. Each phase must run and be demoable before the next begins.
- Store money as integer paise (100 paise = 1 rupee); never use floating-point values for money.
- Store timestamps in UTC and render them in the user's local timezone.

## Out of scope

For the stated scope, real payment settlement, real KYC verification, real route optimization, native mobile apps (the delivery-partner experience is a mobile-first PWA), and multi-country tax are excluded.
